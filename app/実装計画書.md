````markdown
# 動画行動分析ツール 実装計画書
## 会議における服装の影響分析用

---

# 1. 目的

会議実験で撮影した動画を再生しながら、参加者の発話・割り込み・リアクション・姿勢・ジェスチャーをタイムスタンプ付きで記録する。

記録したイベントをタイムライン上で確認・編集し、最終的にCSVとして出力する。

本ツールは、今回の実験に必要な動画アノテーションに限定したMVPとして実装する。

---

# 2. 対象とする実験条件

服装条件：

- スーツ
- クールビズ
- 私服

参加者：

- A
- B
- C
- その他、実験人数に応じて追加可能

---

# 3. 分析項目

分析項目は以下の5種類に限定する。

| 分析項目 | 基準 | イベント形式 |
|---|---|---|
| 発話の偏り（ターン保持率） | その人が1ターンで話している時間 | State |
| 割り込み | 割り込みした回数 | Point |
| リアクション | 自分のターン以外にうなずき・身振り等を行ったタイミング | Point |
| 姿勢 | 分類できる姿勢に変化し終わったタイミング | Point |
| ジェスチャー | 自分の会話ターン中に会話を補助・表現するために行った動作 | Point |

※フィラーは分析対象外とする。

---

# 4. 分析上の基本ルール

## 4.1 発話

参加者が発話している時間を記録する。

同一参加者が連続して発話している区間を1ターンとして扱う。

例：

A
├────────────┤
120.5        135.2

→ 1ターン

start = 120.5
stop  = 135.2

---

## 4.2 割り込み

他者が発話している途中に割り込んだ場合、その発生時点を記録する。

例：

B 発話中
──────────────────

A
          ◆
        割り込み

記録：

participant = A
category = 割り込み
tag = 割り込み
timestamp = 発生時刻

---

## 4.3 リアクション

自分の発話ターン以外に発生したリアクションを記録する。

対象例：

- うなずき
- 身振り
- その他のリアクション

発生したタイミングにタグを付ける。

例：

B 発話中
────────────────────

A
        ◆
      うなずき

---

## 4.4 発話による相槌

リアクションのうち、発話による相槌の場合のみ追加タグを付ける。

例：

- 「うん」
- 「はい」
- 「なるほど」

など、相手の発話に対する相槌として認められるもの。

通常の発話と区別する。

---

## 4.5 姿勢

分類可能な姿勢へ変化した際、

「その姿勢への変化が完了したタイミング」

にタグを付ける。

例：

通常姿勢
    ↓
姿勢変化
    ↓
前傾姿勢になる
    ↓
       ◆
     タグ

姿勢イベントはPoint Eventとして記録する。

---

## 4.6 ジェスチャー

自分の会話ターン中に、会話内容を補助・表現するために行った身体動作を記録する。

対象は手だけに限定しない。

対象：

- 手
- 腕
- 頭
- 上半身
- 下半身
- 全身

ただし、

「明確に会話の補助（表現）として認められるもの」

のみを記録する。

単なる身体の移動や姿勢変更はジェスチャーとして記録しない。

---

# 5. フィラー

フィラーは分析対象外とする。

例：

- 「えー」
- 「あー」
- 「そのー」
- 「なんというか」

など。

フィラーを記録するためのタグは作成しない。

ただし、フィラー以外の発話が継続している場合、その発話時間の扱いについては実験者が事前に統一する。
````

# 14. Event

動画上で実際に記録されたイベント。


# 15. Event Type

Event Typeは2種類のみ。

```text
Point
State
```

---

## Point Event

特定の瞬間を記録する。

対象：

* 割り込み
* リアクション
* 姿勢
* ジェスチャー

データ：

```text
start = timestamp
stop = null
```

---

## State Event

開始から終了までの区間を記録する。

対象：

* 発話

データ：

```text
start = 開始時刻
stop = 終了時刻
```

```text

```

# 27. Timeline

TimelineはSVGベースで実装する。

理由：

* イベント数が極端に多くない
* DOMイベントを利用できる
* クリック処理が簡単
* ドラッグ処理が簡単
* イベント選択が簡単
* State / Pointの描画が容易

---

# 37. CSVの考え方

アプリ内ではIDで管理する。

```text

categoryId
```

```text

```

# 38. 分析値の算出

アプリでは原則として、生データを記録する。

分析値はCSVから算出する。

---

## 発話の偏り

各参加者について、

```text
各ターンの発話時間
```

を取得する。

```text
発話時間 = stop - start
```

例えば：

```text
A
Turn 1 = 12.4秒
Turn 2 = 8.2秒
Turn 3 = 15.7秒
```

から、

* 総発話時間
* ターン数
* 平均ターン時間
* 最大ターン時間

などを算出可能にする。

---

## 割り込み

```text
category = 割り込み
```

のEvent数を参加者ごとにカウントする。

---

## リアクション

```text
category = リアクション
```

のEvent数をカウントする。

さらに、

```text
tag = うなずき
tag = 身振り
tag = 発話相槌
```

などに分けて集計できる。

---

## 姿勢

姿勢イベントを時間順に並べる。

例：

```text
120.0 正面
180.0 前傾
250.0 正面
320.0 腕組み
```

これにより、姿勢の変化回数などを算出できる。

---

## ジェスチャー

```text
category = ジェスチャー
```

のEvent数を参加者ごとにカウントする。

---

# 39. 分析項目とアプリの責任範囲

```text
動画
 ↓
人間による観察
 ↓
アプリでイベント記録
 ↓
CSV
 ↓
統計・分析
```

アプリは、

* 何秒に発生したか
* 誰が行ったか
* 何のイベントか

を正確に記録する。

「服装によって発話時間が増えたか」
「割り込みが増えたか」
などの統計的判断はアプリの責任範囲外とする。

# 44. イベント記録例

動画上で、

「Bが話している」
↓
「Aがうなずく」
↓
「Bが話し終わる」
↓
「Aが発話開始」
↓
「Aが身振りをする」
↓
「Aが前傾姿勢になる」

という状況だった場合、

```text
1.
participant = B
category = 発話
tag = 発話
type = State
start = 100.0
stop = 115.0

2.
participant = A
category = リアクション
tag = うなずき
type = Point
start = 108.5

3.
participant = A
category = 発話
tag = 発話
type = State
start = 116.0
stop = 130.0

4.
participant = A
category = ジェスチャー
tag = ジェスチャー
type = Point
start = 121.5

5.
participant = A
category = 姿勢
tag = 前傾
type = Point
start = 125.0
```

として保存する。

# 46. 最重要設計方針

今回のツールでは、分析基準をアプリの複雑なロジックとして実装しない。

アプリはあくまで、

「動画のどの時点で、誰に、何が起きたか」

を記録する。

基本構造：

```text
Participant
    ↓
誰が

Category
    ↓
何の分析項目か

Tag
    ↓
具体的に何を観察したか

Event
    ↓
いつ発生したか
```

Event Type：

```text
発話         → State
割り込み     → Point
リアクション → Point
姿勢         → Point
ジェスチャー → Point
```
